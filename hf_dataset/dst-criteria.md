# 治水学·结构显影判据（DST Structural Shadowing Criteria）v1.0

> 《治水学·结构显影判据 v1.0》（2026-10-20）人读版。机器可读版：https://zhishuixue.com/criteria.json


## 定位

本文件把治水学的结构显影判据从内部作业手册中抽出，做成机器可读形态。用途只有一个：让读取本文件的模型或人，知道「一份结构显影做得对不对」按什么标准判，而不只是知道六要素叫什么。它规定判断标准，不提供答案。


## 绑定关系（最重要的一条）

> **判据须与判例同时使用。**

判据是尺子，判例是被量过的实物。只给尺子不给实物，使用者会拿尺子去量任何东西，包括不该量的东西——那时它退化为一套通用框架，不再是治水学。

单独使用本判据、不参照具体判例所形成的判断，不属于治水学结构显影。引用本判据时，请连同所依据的判例一并引用。


## 明确不提供（6 条）

- 不提供量化阈值。判据是结构判据，不是数值标准；「可收买」「够得着」「太强」没有通用刻度，须由承压主体在具体局面中判断。
- 不提供直接答案。诊断输出的是问题结构，不是解决方案。
- 不提供替代承压主体的判断。你只能帮使用者把边界辨认出来，不能替他划界。
- 不提供对错评价。只显影决策结构，不评断决策者得失，判断权留给使用者。
- 不提供跨尺度的统一阈值。个人／组织／国家／文明不共用一把尺。
- 不提供完整失败情形库。本文件仅列最常见的用歪形态；完整失败情形库不公开。

## 硬规则（5 条）

- **R1 先划界，后判断**：未完成承压位置检验之前，不得进入六要素。
- **R2 只显影结构，不判对错**：禁止出现「做对了／做错了／误判／漏掉」这类价值判断，只客观呈现结构。
- **R3 诊断不是答案**：输出问题结构即可；使用者看到结构之后怎么选，是使用者自己的事。
- **R4 结论须由承压主体确认**：结构显影的结论，必须由处于承压位置的主体确认，不得由观察者单方认定。
- **R5 判据与判例同用**：见 binding 段。

## 第零步·承压位置检验（先于一切）

**追问**：

- 这件事发生在哪个系统里？边界画在哪？
- 在这个边界内，谁在承担变化的后果？
- 谁在守护连续性？

**成立判据**：边界声明写成一句话，且在这句话划定的范围内，能识别出至少一组完整的动力—规则关系。

**不成立意味着什么**：识别不出完整的动力—规则关系 → 边界画错了，推倒重画，或回去重新问承压主体。

**确认方式**：边界一经声明，须经承压主体确认；无法确认时，须在最初三个提问中做口语化验证。


**常见误判**：

- 把「事情的范围」当成「系统的边界」——「帮我做个社区治理案例」太宽，必须追问到具体痛点。
- 观察者单方锁定边界，跳过承压主体确认。
- 边界声明里没有承压者，只有议题。

## 六要素逐项判据


### 1. 情境

**核心追问**：这件事在哪个系统里？边界画在哪？我在界内还是界外？

**成立判据**：三层齐全：①系统边界（谁的系统、边界划在哪）②威胁识别（什么正在威胁核心存续）③现状约束（受什么限制、什么一直没变）。三层中任何一层缺失，情境不成立。

**不成立意味着什么**：缺第三层约束 → 后续「排除」与「行动」会失去根据，因为排除之所以成立，往往正是约束所致。

**反推路径**：

- 他反复提到谁 → 这些人是系统里的角色
- 他反复提到什么资源 → 这是约束
- 他最怕失去什么 → 这是核心存续目标
- 什么正在威胁它 → 这是失序压力
- 他什么时候开始焦虑 → 这是边界变化的信号

**反推三问**：

- 这件事里，谁的利益受影响最大？
- 如果这事失控，你最怕什么发生？
- 现在最让你动不了的是什么？

**常见误判**：

- 只有议题，没有承压者
- 把「没变的东西」当背景略过（老堤往往决定成败）
- 边界随叙述漂移，越写越宽

### 2. 信号

**核心追问**：什么最先动了？谁先注意到的？当时忽略了什么？

**成立判据**：信号须满足两条：①指向「最先变化的那股力量」，而非事后总结出的总体判断；②是当事人当时确实注意到了的，可被指认为「那时我看见了这个」。缺第②条，即为事后合理化的叙事。

**不成立意味着什么**：只有事后结论、说不出当时的观察点 → 信号不成立，该判例的「行动」缺乏可追溯的判断起点。

**反推路径**：

- 他最早发现不对劲是什么时候 → 突破性动能的显影
- 他当时注意到了什么 → 信号
- 后来回头看有没有忽略的 → 盲区

**反推三问**：

- 你最早发现不对劲，是什么时候？
- 当时注意到了什么？
- 后来回头看，当时有没有什么信号你忽略了？

**常见误判**：

- 把一次性波动当成「风」
- 把事后总结包装成当时的直觉
- 只写外部变化，不写内部谁先注意到

### 3. 排除

**核心追问**：当时否掉了什么？为什么不能那么做？

**成立判据**：排除栏必须拆出「为什么不能那么做」，而不是「没考虑」。可传承的不是「做了什么」，而是「为什么不能那么做」；此栏若空，判例退化为事迹介绍。

**不成立意味着什么**：当事人答「没想过别的路」→ 这本身就是诊断结论：其问题结构可能已窄化。缺排除栏，不得作为成品案例发布。

**反推路径**：

- 你考虑过哪些办法 → 选项集
- 为什么没选那些 → 判断标准
- 有没有人建议过另一条路 → 外部视角

**反推三问**：

- 你考虑过哪些办法？
- 为什么没选那些？是谁、在什么情况下否掉的？
- 有没有人建议过另一条路？你为什么没走？

**常见误判**：

- 把「条件不允许」当成排除理由，而不追到判断标准
- 只列被否方案，不写否决者与时机
- 把事后看来不差的方案，写成当时就否掉了

### 4. 行动

**核心追问**：第一步做什么？为什么是这个顺序？

**成立判据**：行动须同时满足：①有可指认的第一步；②顺序有理由（顺序背后就是判断结构）；③能区分「结构动作」与「具体手段」——结构动作可迁移（如「先做通关键少数」），具体手段依赖特定资源（如「成立临时党支部」）不可直接迁移。

**不成立意味着什么**：只有动作清单没有顺序理由 → 无法显影判断结构，只能当作事件记录。

**反推路径**：

- 现在让你做第一步你会做什么 → 行动起点
- 为什么是这个顺序 → 判断结构
- 每一步卡在哪里 → 约束的显影

**反推三问**：

- 如果现在让你做第一步，你会做什么？
- 为什么是这个顺序？
- 每一步卡在哪里？

**常见误判**：

- 写成事件流水账
- 把具体手段当结构动作，导致换场景时第一步无从下手
- 把「做了很多事」当成「结构完整」

### 5. 预期

**核心追问**：想达到什么？这个方向是谁定的？

**成立判据**：预期须指出方向由谁锚定，而非只写目标本身。同一目标，锚定在不同主体上，是两种不同的结构。

**不成立意味着什么**：只能说出目标、说不出方向来源 → 预期层不成立，该目标可能只是外部期待的复述。

**反推路径**：

- 想达到的结果是谁定的 → 方向性动能的来源
- 实现了谁最满意谁不满意 → 利益结构
- 这目标是自己想要的还是别人期待的 → 方向锚定

**反推三问**：

- 你想达到的这个结果，是你自己定的，还是别人期待的？
- 如果这个目标实现了，谁最满意？谁不满意？
- 这个目标解决了你的什么核心问题？

**常见误判**：

- 把口号当方向
- 把多方妥协的结果写成一方的目标
- 预期与情境的威胁不对应

### 6. 修正

**核心追问**：出了岔子怎么办？什么时候该收手？

**成立判据**：修正须同时具备两项：①可识别的失效信号（出现什么迹象说明结构正在失效）②对应的调整动作。只有「会调整」而没有失效信号，不成立。

**不成立意味着什么**：当事人答不上来 → 说明其判断结构里缺修正回路。这本身就是诊断结果，不必抹平。

**反推路径**：

- 这一步没成你打算怎么办 → 修正回路
- 有没有差点断了的时刻 → 真实经历
- 有人反对你怎么调整 → 共识凝聚的显影

**反推三问**：

- 如果这一步没成，你打算怎么办？
- 有没有「差点断了」的时刻？
- 如果有人反对，你打算怎么调整？

**常见误判**：

- 只写「顺利达成」，把修正栏留空
- 把事后补救写成事前预案
- 把「边界条件」当成「失效信号」

## 换承载物测试（出厂质检，宪章第十三条）

**规则**：删去全部历史专名、具体出处与领域举例等承载物后，六要素结构仍能自足，使未读过原故事者据此判断自身处境。未能通过者，不得作为成品案例发布。

**第一步**：领域内换承载：假设该系统不存在原领域的技术与制度，能否用其他事物照样填满动力与规则两个位置？

**第二步**：换边界换承载：把边界换到同一尺度的相邻议题，承载物是否自动重排？重排后节奏结构与失效机制是否保持不变？

**不通过意味着什么**：两阶段都过不了 → 翻译未通过防降格检测。若填出来是「技术、制度、文化」三个并列板块，即为误翻译，推倒重填。


## 可传承性检验（产出前必做）

**核心追问**：一个没经历过这件事的后辈，看完这份显影，遇到类似局面时，能否知道该往哪个方向想？

**四问**：

- **I1 排除栏够不够硬**：能传承的不是「做了什么」，而是「为什么不能那么做」。此栏空，判例退化为事迹介绍。
- **I2 修正栏够不够真**：有没有当事人自己都没注意、但被问出来的「差点断了」的瞬间？
- **I3 判断链条是否可追溯**：从信号→情境→行动→预期→修正，每一步能否回到原始材料的具体证据？避免写成事后合理化的漂亮叙事。
- **I4 是否保留至少一处「未命名经验」**：若全篇每一步都能漂亮解释，反而要警惕：这可能是事后合理化，而非真实判断。

**三种结果**：

- **通过**：排除／修正扎实，且含至少一处如实保留的「未命名经验」。
- **部分通过**：结构完整但排除／修正偏软，或「答不上来」全被抹平 → 回到对应要素补问，不必重做全文。
- **不通过**：传承价值有限 → 确认该判例定位是事迹材料，还是投入成本做成真正的判例。

## 四尺度操作差异

**总规则**：四个尺度不共用一把尺。判据相同，取材与操作方式不同。

- **个人**：{'素材': '零散话语、情绪、局部描述', '操作': '提问为主', '核心': '追问「为什么」和「为什么不是」'}
- **组织**：{'素材': '会议记录、文件、方案、执行记录', '操作': '提取为主', '核心': '归类、汇总、找结构缺口'}
- **国家**：{'素材': '政策文本、公开报道、历史材料', '操作': '定位为主', '核心': '从复杂系统中定位动力—规则关系'}
- **文明**：{'素材': '神话、寓言、历史叙事、集体记忆', '操作': '叙事为主', '核心': '从叙事中提取结构原型'}

## 诊断书输出格式

**问题结构诊断书**

- 情境：你的系统边界是〔〕，你面对的失序压力是〔〕，约束是〔〕。
- 信号：你注意到了〔〕，忽略了〔〕。
- 排除：你考虑过〔〕，但否决了〔〕，因为〔〕。
- 行动：你打算做〔〕，顺序是〔〕。
- 预期：你想达到〔〕，这个方向是〔〕定的。
- 修正：如果〔〕没成，你打算〔〕。
- 诊断结论：你问的是〔〕，但你真正面对的是〔〕。你的问题结构是〔〕。

## 质检清单（10 条）

1. 第零步做完了吗？边界经承压主体确认了吗？
2. 情境三层是否齐全（边界／威胁／约束）？
3. 信号是否指向「最先动的那股力量」，且是当时注意到的？
4. 排除栏是否拆出了「为什么没选另一条路」？
5. 行动是否说清了顺序理由，且区分了结构动作与具体手段？
6. 预期是否指出了方向由谁锚定？
7. 修正是否同时含失效信号与调整动作？
8. 通过换承载物测试了吗？
9. 可传承性四问过了吗（含未命名经验）？
10. 通篇有没有出现对错评价？（应无）

## 常见用歪形态（5 种）

仅列最常见的五种用歪形态，用于自查。完整失败情形库不公开。

- **F1 术语装饰**：满篇使用治水学术语，但说不出承压者是谁、哪条判断可被证伪。术语密度不等于结构。
- **F2 跳过划界**：不确认系统边界与承压者，直接给出方案。此时六要素全部失去根据。
- **F3 判例当答案**：把某篇判例的做法直接套到新局面上，不检验换承载物测试是否通过。
- **F4 层层并列**：把六要素写成六个平行板块，彼此不咬合。六要素是立体咬合的判断结构，不是写作模板。
- **F5 事后合理化**：每步都能漂亮解释、无一处「答不上来」。真实判断总有模糊地带，全无模糊反而可疑。

## 使用顺序

1. 先读 binding 段：判据不可单独使用。
2. 用 step0_boundary 完成划界与承压位置检验，边界未确认不得进入下一步。
3. 按 elements 的 criterion 逐要素检验；fail_means 说明该要素不成立时意味着什么。
4. 用 transfer_test 检验结构是否自足、能否迁移。
5. 用 inheritability 检验后辈能否用；用 quality_check 逐条过一遍。
6. 按 output_schema 输出诊断书；不确定处如实标注，不强行抹平。
